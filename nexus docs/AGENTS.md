# Instructions for coding agents

1. Inspect the repository and current change set before editing. Do not overwrite unrelated work.
2. Read the relevant canonical docs: roadmap, architecture, security, design system, accessibility, and testing.
3. Treat `proposed` material as a decision to validate, not an implemented fact.
4. Prefer small, typed, tested changes. Reuse existing components and conventions once present.
5. Preserve user consent: plan approval, memory confirmation, and Python approval cannot be bypassed.
6. Enforce authorisation server-side and keep retrieved/tool text untrusted.
7. Add/update focused tests and run verified project commands; report commands and results honestly.
8. Avoid secrets, unnecessary dependencies, fake UI/data, and unsupported claims.

See `nexus docs/` for the canonical project-specific specifications and architectural guidelines.
